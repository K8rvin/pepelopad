# Руководство для агента

## Текущее состояние

Проект переводится из одного HTML в модульную архитектуру. Общий план и критерии этапов находятся в `REFACTORING_PLAN.md`; после изменения этапа обновляй его статус.

`index_v4.html` — замороженный эталон поведения. Файлы в `Архив/` не изменять. Новая рабочая точка входа — `index.html`.

## Команды

```bash
npm install
npm run dev
npm run build
npm test
npm run format
npm run format:check
```

## Архитектурные правила

- Сохранять Canvas 2D и DOM-интерфейс; не менять движок без отдельного решения пользователя.
- Данные предметов, рецептов, навыков и квестов хранить в `src/data/`, отдельно от механик.
- Игровые системы размещать в `src/systems/`, генерацию мира — в `src/world/`, отрисовку — в `src/render/`, DOM — в `src/ui/`.
- Не добавлять глобальное состояние в новые модули. У каждой подсистемы должен быть понятный владелец данных.
- Отрисовка только читает состояние. События не должны скрытно менять не связанные с ними системы.
- Для генерации мира использовать seeded RNG, а не глобальный `Math.random`.
- Не сериализовать живые объекты напрямую при дальнейшей переработке сохранений; использовать версионированную схему и миграции.
- Коллекции ассетов не копировать целиком. В `public/assets/` помещать только отобранные файлы и необходимые лицензии.
- Не минифицировать исходники вручную.

## Проверка изменений

После изменений выполнить доступные проверки:

```bash
npm run format:check
npm test
npm run test:e2e
npm run build
```

Дополнительно проверять относящийся к изменению игровой сценарий в браузере. Нельзя считать успешный синтаксический разбор доказательством работоспособности.

При изменении данных проверять все ссылки на ID предметов, рецептов, наград, иконок и целей заданий. При изменении квестов проверять всю основную цепочку и побочные задания. При изменении автомобилей проверять посадку, движение, столкновения, заправку, багажник и сохранение.
