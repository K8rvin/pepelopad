# Руководство для агента

## Текущее состояние

Проект переводится из одного HTML в модульную архитектуру. Общий план и критерии этапов находятся в `REFACTORING_PLAN.md`; после изменения этапа обновляй его статус.

`index_v4.html` — замороженный эталон поведения. Файлы в `Архив/` не изменять. Новая рабочая точка входа — `index.html`.

## Команды

```bash
npm install
npm run dev
npm run build
npm test
npm run format
npm run format:check
```

## Архитектурные правила

- Сохранять Canvas 2D и DOM-интерфейс; не менять движок без отдельного решения пользователя.
- Данные предметов, рецептов, навыков и квестов хранить в `src/data/`, отдельно от механик.
- Игровые системы размещать в `src/systems/`, генерацию мира — в `src/world/`, отрисовку — в `src/render/`, DOM — в `src/ui/`.
- Не добавлять глобальное состояние в новые модули. У каждой подсистемы должен быть понятный владелец данных.
- Отрисовка только читает состояние. События не должны скрытно менять не связанные с ними системы.
- Для генерации мира использовать seeded RNG, а не глобальный `Math.random`.
- Не сериализовать живые объекты напрямую при дальнейшей переработке сохранений; использовать версионированную схему и миграции.
- Коллекции ассетов не копировать целиком. В `public/assets/` помещать только отобранные файлы и необходимые лицензии.
- Не минифицировать исходники вручную.

## Инструменты: консультации Qwen4-Max

Для сложных и творческих задач (сюжет, диалоговая система, навыки и характеристики, поведение врагов, развитие базы с выжившими, архитектурные вопросы движка/рендера) сначала запрашивай консультацию Qwen4-Max, а затем реализуй. По каждой механике: инструменты и план действий от консультации, решение принимай по ней (или зафиксируй в плане, почему отступил).

**Когда консультироваться обязательно:**
- новая сложная механика (интерьеры, машины, лагеря, навыки, AI врагов, сюжет);
- архитектурный тупик (порядок наложения, повороты спрайтов, этажи, сохранения);
- визуальный стиль и пайплайн ассетов.

**Как вызвать (Windows, cURL):**

1. Тело запроса — JSON-файл во временной папке (не экранировать в PowerShell!):
   `C:\Users\Andrey\AppData\Local\Temp\opencode\qwen_<тема>.json`
   ```json
   {
     "model": "qwen4-max",
     "enable_thinking": true,
     "messages": [
       { "role": "system", "content": "Ты — эксперт по <область>. Отвечай конкретно, с числами и планом, на русском." },
       { "role": "user", "content": "== КОНТЕКСТ ==\n<текущая архитектура, ограничения>\n\n== ВОПРОСЫ ==\n1. ...\n2. ..." }
     ]
   }
   ```
2. Вызов:
   ```powershell
   $key = (Get-Content .env | Where-Object { $_ -match 'DASHSCOPE_API_KEY=' }) -replace 'DASHSCOPE_API_KEY=', ''
   curl.exe -s -X POST "https://ap-southeast-1.maas.qwencloudapi.com/compatible-mode/v1/chat/completions" `
     -H "Authorization: Bearer $key" -H "Content-Type: application/json" `
     -d "@<путь_к_json>" -o "<ответ.json>" -w "HTTP %{http_code}, %{time_total}s\n"
   ```
3. Ключ — в `.env` (`DASHSCOPE_API_KEY`), файл в `.gitignore`.

**Правила:**
- Включай `enable_thinking` (ответ 2–6 минут, но глубже). Модель: `qwen4-max`.
- В контексте давай: текущую архитектуру, числа (размеры мира, FPS, бюджеты), что уже сделано. Проси конкретику: числа, формулы, псевдокод, критерии приёмки.
- Ответ сохраняй в `docs/<тема>-qwen.md` (как `docs/visual-redesign-qwen.md`, `docs/interiors-qwen.md`, `docs/vehicles-qwen.md`).
- Следуй консультации; отступление фиксируй в `REFACTORING_PLAN.md` с причиной.
- Один вызов = одна тема; не гоняй серии для «лучшего» ответа — если ответ слабый, уточни контекст, а не повторяй запрос.

## Проверка изменений

После изменений выполнить доступные проверки:

```bash
npm run format:check
npm test
npm run test:e2e
npm run build
```

Дополнительно проверять относящийся к изменению игровой сценарий в браузере. Нельзя считать успешный синтаксический разбор доказательством работоспособности.

При изменении данных проверять все ссылки на ID предметов, рецептов, наград, иконок и целей заданий. При изменении квестов проверять всю основную цепочку и побочные задания. При изменении автомобилей проверять посадку, движение, столкновения, заправку, багажник и сохранение.
