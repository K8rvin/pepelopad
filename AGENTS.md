# Руководство для агента

## Текущее состояние

Игра «МЁРТВЫЙ РАЙОН» (бывш. ПЕПЕЛОПАД) — модульный изометрический survival на Canvas 2D. Общий план и критерии этапов находятся в `REFACTORING_PLAN.md`; после изменения этапа обновляй его статус.

Единственная рабочая точка входа — `index.html` (город, `src/iso/`). Старая версия с OSM-Волгоградом удалена полностью (этап 48): файлы, архив и записи очищены, git-история переписана без путей старой версии.

## Команды

```bash
npm install
npm run dev
npm run build
npm test
npm run format
npm run format:check
```

## Архитектурные правила

- Сохранять Canvas 2D и DOM-интерфейс; не менять движок без отдельного решения пользователя.
- Данные предметов, рецептов, навыков, зомби и квестов хранить в `src/iso/data/`, отдельно от механик.
- Игровые системы размещать в `src/iso/systems/`, генерацию мира — в `src/iso/world/`, отрисовку — в `src/iso/render/`, DOM — в `src/iso/ui/`, сохранения — в `src/iso/persistence/`.
- Не добавлять глобальное состояние в новые модули. У каждой подсистемы должен быть понятный владелец данных.
- Отрисовка только читает состояние. События не должны скрытно менять не связанные с ними системы.
- Для генерации мира использовать seeded RNG, а не глобальный `Math.random`.
- Не сериализовать живые объекты напрямую при дальнейшей переработке сохранений; использовать версионированную схему и миграции.
- Коллекции ассетов не копировать целиком. В `public/assets/` помещать только отобранные файлы и необходимые лицензии.
- Не минифицировать исходники вручную.

## Инструменты: консультации Qwen4-Max

Директива пользователя от 20.11.2026: текущий агент и есть Qwen4-Max, с которым советовался прошлый агент. Внешние консультации по API не требуются — агент сам анализирует и принимает решения по архитектуре и сложным механикам (сюжет, диалоги, навыки, AI врагов, лагеря, база, визуальный стиль). Обоснования решений фиксировать в `REFACTORING_PLAN.md` (при необходимости — в `docs/`). Исторические консультации прошлых сессий лежат в `docs/*-qwen.md` и остаются справочным материалом.

## Проверка изменений

После изменений выполнить доступные проверки:

```bash
npm run format:check
npm test
npm run test:e2e
npm run build
```

Дополнительно проверять относящийся к изменению игровой сценарий в браузере. Нельзя считать успешный синтаксический разбор доказательством работоспособности.

При изменении данных проверять все ссылки на ID предметов, рецептов, наград, иконок и целей заданий. При изменении квестов проверять всю основную цепочку и побочные задания. При изменении автомобилей проверять посадку, движение, столкновения, заправку, багажник и сохранение.
