# План развития и рефакторинга «ПЕПЕЛОПАД»

Актуальный игровой эталон: `index_v4.html`.
Предыдущие версии хранятся в `Архив/` и не изменяются при рефакторинге.

## Цель

Перейти от одного HTML с глобальным состоянием к модульному браузерному проекту, который удобно развивать вручную и через AI-агента, не потеряв существующий игровой процесс.

## Принципы

- Не переписывать игру с нуля и не менять движок.
- Сохранить Canvas 2D, DOM-интерфейс, текущий баланс и механики.
- `index_v4.html` остаётся эталоном поведения до завершения миграции.
- Каждый этап должен заканчиваться работающей сборкой.
- Сначала переносим поведение, затем исправляем архитектурные проблемы и добавляем контент.
- Исходники не минифицируем; минификация выполняется только production-сборкой.
- Внешние коллекции не копируются в проект целиком: используются только отобранные ассеты.

## Целевая структура

```text
zombie/
├── index.html
├── package.json
├── AGENTS.md
├── REFACTORING_PLAN.md
├── public/assets/
├── src/
│   ├── main.js
│   ├── game.js
│   ├── core/          # цикл, ввод, события, математика, seeded RNG
│   ├── data/          # предметы, рецепты, навыки, квесты, параметры мира
│   ├── world/         # генератор города, чанки, пространственные индексы
│   ├── systems/       # игрок, бой, зомби, авто, инвентарь, крафт, квесты
│   ├── render/        # отрисовка, свет, спрайты, карта
│   ├── ui/            # HUD, панели, диалоги
│   └── persistence/   # сохранения и миграции
└── tests/
    ├── unit/
    └── e2e/
```

## Обязательные проверки

Каждая завершённая миграционная итерация:

```bash
npm run validate
npm test
npm run build
```

Браузерные сценарии по мере внедрения Playwright:

```bash
npm run test:e2e
```

Минимальные сценарии:

- главное меню и новая игра открываются без ошибок консоли;
- пролог проходится и пропускается;
- открываются все вкладки, включая крафт и багажник;
- автомобиль с топливом проезжает дистанцию и расходует бензин;
- деревья и машины не появляются внутри зданий;
- полный инвентарь не дублирует предметы;
- рассадник уничтожается стрельбой;
- кампания m1–m10 и задание с грузом завершаются;
- сохранение восстанавливает игрока, машины, лагеря и задания.

## Правила для последующих изменений

- Для новой механики сначала определить модуль-владелец состояния.
- Новые предметы и рецепты добавлять только через данные и валидируемые ID.
- Отрисовка не изменяет игровое состояние.
- Старые сохранения поддерживать миграциями либо явно версионировать несовместимость.
- Не оставлять новые глобальные переменные без необходимости.
- Не считать этап завершённым только по успешному синтаксическому разбору: проверять реальный сценарий.

## Текущий статус

Этап 1 завершён: Vite, форматирование и базовые тесты работают.
Этап 2 завершён: данные, валидатор, события и unit-тесты генераторов готовы. Процедурные тайлы, персонажи, постройки и иконки разделены на модули в `src/render/`; внешние ассеты по-прежнему заменяют процедурные fallback-спрайты после их инициализации.
Этап 3 завершён: мир, менеджер чанков, инвентарь, багажник, автомобили и столкновения выделены в отдельные модули.
Этап 4 завершён: события, прогресс и сюжетные выдачи выделены, кампания и Матка исправлены.
