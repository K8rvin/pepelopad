## 1. МЕТРИКИ ИЗОМЕТРИИ

### Базовое решение: тайл 64×32 = 1×1 метр

| Параметр | Значение | Обоснование |
|---|---|---|
| Тайл (ромб) | **64×32 px** = 1 м² | 1 м по оси = вектор (32, 16), длина 35.8 px ≈ ваш целевой «1 м = 32 px» |
| Базовые векторы | `ex=(+32,+16)`, `ey=(-32,+16)`, `ez=(0,-32)` | высота 1 м = 32 px по вертикали |
| Высота этажа | **96 px** (3 м) | панелька 2 этажа = 192 px, 3 этажа = 288 px |
| Спрайт стены (1 тайл) | **64×128** (96 стена + 32 ромб-подошва) | + парапет/свес крыши 16–24 px → холст 64×160 |
| Персонаж | холст **64×96**, тело ~26×58 px (1.8 м) | голова 10–12 px — минимум для читаемой эмоции |
| Зомби | тот же риг 64×96 | переиспользование анимаций = экономия 40% арта |
| Машина (ВАЗ, 4.3×1.7 м) | холст **224×160** | 4 направления + зеркало = 8 |
| Дерево | холст **128×160** (4–5 м) | крона перекрывает 2–3 тайла |
| Фонарный столб | 32×192 (6 м) | |

**128×64 не берите как игровой тайл** — это либо сетка 2×2 м (теряете точность коллизий и лута), либо 1 м при 2× зуме (видите 15×15 м — для шутера с машинами слепота). 128×64 используйте как **мастер-исходник** (авторите в 2×, даунскейл в 64×32 nearest — получите бесплатный антиалиасинг контуров и запас для зума).

### Что видно на экране (1280×720, zoom 1.0)
- Спан по (x−y): 1280/32 = **40 м**; по (x+y): 720/16 = **45 м**
- Видимая площадь = 40×45/2 = **900 м²** ≈ квадрат 30×30 м
- Против текущих 4480 м² → **в 5 раз плотнее**, плюс застройка вместо пустырей
- Зум-лестница: **1.0 (улица, по умолчанию) / 2.0 (интерьер, целочисленный → без мерцания)**. 1.5 не делайте — нецелый зум у пиксель-арта даёт «пляшущие» пиксели.

### Проекция и обратная проекция (мир остаётся прямоугольным, в метрах!)
```js
sx = (wx - wy) * 32;
sy = (wx + wy) * 16 - wz * 32;
// пик по земле (z=0):
wx = sx/64 + sy/32;
wy = sy/32 - sx/64;
```
Физика, коллизии, ИИ, пули, лут — **не трогаем**, они в top-down метрах. Меняется только рендер и mouse-picking.

### Z-сортировка
Ключ: **`depth = max(wx + wy)` по footprint объекта** (передний угол), не экранный Y центра.

```js
// слои: 0 = земля/декали (в чанке), 1 = стены/пропсы, 2 = сущности, 3 = крыши
bucket = Math.floor((maxX + maxY) * 2);   // полуторные корзины
key    = bucket * 4 + layer;
```
- **Стены на границах тайлов**: южная/восточная кромка → `depth = x+y+2−0.01` (перед содержимым тайла), северная/западная → `x+y+0.01`. Это правило решает 90% «персонаж провалился за стену».
- **Крупные объекты (машина 2×5 тайла)**: `depth = center + 0.6*(halfW+halfH)` + ручное поле `depthBias` в JSON спрайта. Не пытайтесь сделать топологическую сортировку — O(n²), и PZ тоже страдает на машинах.
- **Сортировка**: не `Array.sort` на 1200 элементов каждый кадр, а **bucket sort** по 90–120 корзинам (диапазон видимых `x+y`), стабильный порядок вставки. ~0.2–0.4 мс вместо 1.5 мс.
- **Cutaway**: крыши — отдельный проход с `globalAlpha=0` когда игрок внутри; южные стены, чей bbox перекрывает игрока, → альфа 0.25 + dither.

## 4. РЕНДЕР НА CANVAS 2D

### Чанки
- **Чанк = 8×8 тайлов (8×8 м)** → экранный bbox **512×256 px** = 0.13 Мпикс = **0.5 МБ** RAM.
- 16×16 даст 1024×512 = 2 МБ/чанк — при LRU 40 это 80 МБ и перепечка 15–25 мс. **8×8 лучше**: перепечка **3–6 мс**, влезает в бюджет 1 чанк/кадр.
- Видимо на экране 6–12 чанков. **LRU-кэш 160 чанков = 80 МБ** — потолок для браузера.
- Ромб занимает 50% bbox → половина канваса прозрачная. Это цена простоты, принять.
- Padding **+2 px** по краям и рисование с округлением до целых — иначе швы-волосы между чанками.
- Карта 1.5×1.5 км = 188×188 = 35 344 чанка. Данные тайлов: 4 слоя × Uint8Array(2.25M) = **9 МБ** — нормально. Печка — только по требованию, **бюджет 1 чанк/кадр**, очередь с приоритетом по расстоянию к камере.

### Что печём в чанк (один раз)
1. Земля/асфальт/тротуар — 64 `drawImage`.
2. Декали (трещины, масло, пепел) — `multiply`/`overlay`, 20–40 вызовов.
3. **AO у стен**: полоска-градиент 8 px вдоль основания, `multiply`, alpha 0.35. Пре-рендер 4 спрайта (по orientation), не `createLinearGradient` в цикле.
4. **Тени зданий**: полигон = footprint, экструдированный вдоль солнца `(+10,+5) px на метр высоты`. 9 м дом → тень (90,45). Заливка `#10141a` @ 0.35, `filter:'blur(3px)'` — **только на этапе печки**, один раз.
5. Пепельный noise: тайлящаяся текстура 256×256, `overlay` @ 0.08.

**Стены, пропсы, сущности в чанк НЕ печём** — иначе не интерливить персонажей и не делать cutaway.

### Кадровый бюджет (цель 16.6 мс)

| Проход | Вызовы | мс |
|---|---|---|
| Чанки земли | 6–12 drawImage | 1.0–1.5 |
| Tall-слой (стены/пропсы/сущности), bucket sort | 400–900 drawImage | 2.5–3.5 |
| Крыши/cutaway | 50–150 | 0.5 |
| Освещение (half-res) | 2 канваса 640×360 + 24光源 | 1.5–2.5 |
| Пост (грейдинг, виньетка, зерно, пепел) | 4–6 fillRect/drawImage | 1.0 |
| Логика/ИИ/физика | — | 3.0–4.0 |
| **Запас на GC** | — | **3.0** |

### Ночное освещение — дёшево и правильно
```
1. lightCanvas 640×360 (ПОЛОВИНА разрешения — свет мягкий, разницы нет)
2. fillStyle ambient rgba(10,14,24,0.86) → fillRect
3. globalCompositeOperation='destination-out'
   drawImage(preRenderedLightSprite, ...)   // НЕ createRadialGradient каждый кадр!
4. main.drawImage(lightCanvas, 0,0, 1280,720)  // растяжка ×2, smoothing ON
5. warmCanvas 640×360: те же спрайты с 'lighter', цвет #ffb45c
   main.globalCompositeOperation='overlay'; drawImage(warmCanvas) @ alpha 0.55
```
- **Пре-рендер 4 спрайтов света**: фонарь-**эллипс 256×128** (лужа на земле в iso — эллипс 2:1, не круг! это ошибка №1 в освещении изометрии), конус из окна 256×192, фара-конус 384×160, костёр-круг 192×192.
- Куллинг: только источники в экране +128 px, **cap 24/кадр**, сортировка по яркости.
- Мерцание: `alpha *= 0.9 + 0.1*noise(t)` — 1 умножение, не пересчёт градиента.

### Цветокор и пост
- **Никакого `getImageData`/`putImageData` в кадре** — 3.7 МБ пикселей = 20–40 мс.
- Грейдинг = 2 fillRect: `multiply` tint + `overlay` контраст-подложка.
- Виньетка: пре-рендер PNG 1280×720, `multiply` @ 0.45 — 0.3 мс.
- Зерно: 3 канваса 256×256 с noise, циклически, `overlay` @ 0.05, случайный offset — 0.4 мс. **Зерно только в рантайме, не в ассетах.**
- Пепел: 250–350 частиц 2–3 px, 2 параллакс-слоя, батч через `fillRect` одного цвета — 0.6 мс.
- Backing store **фиксированный 1280×720**, апскейл через CSS + `image-rendering: pixelated`. DPR игнорируем сознательно (пиксель-арт).
- Камера округляется до целых пикселей — иначе дизеринг «кипит».

### Атласы
- terrain 1024×1024 (256 тайлов 64×32 влезает 512) — 4 МБ
- objects 2048×2048 — 16 МБ. **Не больше 4096** — мобильные Safari режут.

## 5. Когерентность разнородных ассетов

### Единый офлайн-«утюг» (Node + sharp / Python + PIL), 7 шагов для каждого ассета
1. **Ресемпл** к единой тексельной плотности: 1 px = 3.125 см (1 м / 32). AI-картинку 1024 px даунскейлить в 64–128 nearest — это само по себе унифицирует 70% различий.
2. **Квантование в мастер-палитру 32 цвета** (12 базовых + 20 производных рампов) + Bayer 4×4 дизеринг силой 0.15.
3. **Единое направление света**: солнце с NW, экранный вектор `(-1, -0.5)`. Верхние грани +8% lightness, юго-восточные −12%, северо-западные +4%.
4. **Единая политика контура**: выбрать одно — либо 1 px `#10141a` @ 40% alpha, либо без контура. Смешивать нельзя, это главный признак «сборной солянки».
5. **Тени приводим к одному оттенку**: `multiply #222a34`, не чёрный и не серый.
6. **Contact shadow**: эллипс 2:1 под каждым объектом, `#10141a` @ 0.3, ширина = 0.8 footprint. Дёшево и сажает объект на землю.
7. **Пепельная пыль** на верхние грани: noise @ 0.1 — общий «знаменатель» всех ассетов.

### Размерный ряд (жёстко фиксировать в стандарте)
| Объект | Холст | Anchor |
|---|---|---|
| Тайл земли | 64×32 | центр ромба |
| Стена | 64×160 | низ-центр подошвы |
| Пропс мелкий | 64×64 | низ-центр |
| Персонаж/зомби | 64×96 | низ-центр |
| Машина | 224×160 | низ-центр |
| Дерево | 128×160 | низ-центр |

Каждый спрайт — JSON: `{w, h, anchorX, anchorY, footprint:[w,h], zOffset, depthBias}`. Без этого зоопарк паков не соберётся.

### Приёмочный тест «3 секунды»
Сцена-стенд: 10 случайных ассетов на одном экране. Смотреть **прищурившись / зум 25%**. Если что-то «выпрыгивает» по насыщенности или value — править, не обсуждать. Прогонять каждый новый пак через этот тест **до** интеграции.

### AI-генерация: промпт-шаблон
Фиксированный суффикс во всех запросах: *«muted desaturated palette, ash grey and dirty beige, overcast flat lighting from top-left, no bright colors, seamless tileable texture, no perspective, orthographic flat, grime and cracks»*. Генерить **плоские текстуры 512×512**, проецировать самим:
```js
ctx.setTransform(1, 0.5, -1, 0.5, ox, oy); // квадрат → ромб 2:1
```
Так вы получаете консистентную геометрию (её задаёте вы) и вариативность текстур (её даёт модель).

## 6. ТОП-5 ЛОВУШЕК ПЕРЕХОДА TOP-DOWN → ISO

**1. Переписать физику/коллизии под изометрию.**
Мир должен остаться прямоугольным 2D в метрах, iso — только матрица投影. Иначе пули летят «не туда», ИИ ломается, а сохранения несовместимы. Отдельно: **mouse-picking по крыше ≠ тайл под ней**. Пик по земле (z=0) + отдельный проход по bbox кликабельных спрайтов с альфа-тестом. Формулы обратной проекции — в п.1.

**2. Сортировка по экранному Y центра объекта.**
Классика: персонаж «проваливается» за стену, машина рвётся пополам, дерево рисуется поверх дома. Нужен `max(wx+wy)` по footprint + правила для стен на кромках + стабильные корзины. Заложите **отладочный режим с подсветкой depth-корзин** — сэкономит неделю.

**3. Запечь стены и сущности в чанк-канвасы.**
Получите: невозможность интерливинга, невозможность cutaway крыш, и перепечку 15–25 мс при каждом открытии двери (фриз). Печём **только землю + декали + AO + тени**. Стены — per-frame `drawImage` (500–900 вызовов = 3 мс, это дёшево). Rebake — не больше 1 чанка за кадр.

**4. Освещение и цветокор «в лоб».**
`createRadialGradient` × 30 источников + `filter:'blur()'` + `getImageData` на весь экран = 25–40 мс, игра идёт в 25 fps. Только пре-рендеренные спрайты света, half-res буфер, composite-операции. И **лужи света — эллипсы 2:1**, круглые выдают «top-down под наклоном».

**5. Недооценка объёма арта и плотности.**
Iso требует ×2–4 больше спрайтов: 2 ориентации стен, углы, 4–8 направлений персонажей, переходы земли. Плюс пустая земля в iso бросается в глаза сильнее. **Делайте vertical slice: один квартал 60×60 м (3600 тайлов), все слои, ночь+день, 20 зомби, машина — 16–24 часа.** Замерьте fps и трудозатраты, только потом масштабируйте на 1.5 км.

### Нормативы плотности города (утвердить ДО генерации карты)
- Застроено **45–55%** площади (сейчас у вас, судя по описанию, 10–15%)
- Дорога **8 м** (2 полосы) + тротуары 2×3 м = 14 м коридор, не 30+
- Дом-панелька **12×30 м**, 2–3 этажа; двор **25×30 м**
- Расстояние между домами **15–20 м**
- В кадре 900 м² должно быть: **2–4 здания, 3–6 машин, 8–15 пропсов, 4–8 деревьев**
- **Мамаев курган**: реальные 85 м статуи = 2720 px — нереально. Террасы по 1.5 м (48 px) × 8 уровней = 12 м подъёма, статуя — спрайт 160×420 (≈13 м) + силуэт на дальнем фоновом слое. Читается как достопримечательность, не ломает масштаб.

**Бонус-ловушка №6:** нецелый зум и `devicePixelRatio` у пиксель-арта → мерцающие контуры. Фиксированный буфер 1280×720, целочисленные зумы {1, 2}, `imageSmoothingEnabled=false` для мира и `true` только для светового буфера.
