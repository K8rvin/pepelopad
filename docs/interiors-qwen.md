# Консультация Qwen4-Max: интерьеры в изометрии (17.11.2026)

# Главный вывод

**Одна карта, один координатный мир, интерьеры — «ленивые локальные патчи» зданий с индексом этажа.** Это ровно то, что делает PZ (единый world-grid с Z-уровнями), и это единственный вариант, который не сломает твои зомби/окна/бесшовный вход. Отдельная сцена на здание — тупик при 1400 зданиях и живых зомби.

Ниже — конкретика по всем 7 пунктам.

---

## 1. АРХИТЕКТУРА: одна карта + lazy-интерьеры

### Сравнение

| Критерий | Одна карта + cutaway | Сцена на здание |
|---|---|---|
| Вход/выход | 0 мс, смена флага | телепорт/фейд, дублирование состояния |
| Вид из окна | бесплатно (мир уже отрисован) | нужен рендер «мира-заглушки» |
| Зомби заходят внутрь | один A*, дверь = ребро графа | миграция сущности между сценами, рассинхрон |
| Spatial grid | одна, + измерение level | две, cross-layer запросы у дверей |
| Память | данные 24 МБ на все 1400 | ×2 копии сущностей/лута |
| Сейв | seed + дельты | отдельные состояния сцен |

### Что НЕ делать
Полный 3D-грид города: `1500×1500×8 = 18 млн ячеек`, 4 массива Uint8 = **72 МБ** и 18 млн инициализаций. Отклонить.

### Что делать

```js
// Мир остаётся 2D. Интерьер — локальный патч здания.
Building = {
  id, ox, oy,          // origin в метрах (мировые координаты)
  w, h, floors,        // 12..30 × 12..24, 1..4
  type,                // panelka | shop | school | hospital
  seed,                // uint32 = hash(id)
  state: 'shell' | 'generated' | 'active',
  levels: [ LevelData ] // создаётся лениво
}

LevelData = {
  floorTex: Uint8Array(w*h),   // материал пола / role tint
  wall:     Uint8Array(w*h),   // биты N=1 E=2 S=4 W=8 (стена на ребре)
  door:     Uint8Array(w*h),   // биты: проём есть
  doorState:Uint8Array(w*h),   // 0 closed 1 open 2 locked 3 broken
  room:     Uint16Array(w*h),  // id комнаты (0 = коридор)
  occ:      Uint8Array(w*h),   // мебель блокирует
  bodies:   [AABB],            // мебель, 20–40 шт
  containers:[{id,x,y,kind,seed,searched}]
}
```

**Бюджет данных на здание:** `30×24×4 = 2880` ячеек × 8 байт ≈ **23 КБ**. Все 1400 зданий ≈ **24–32 МБ**. Это ничто — данные можно держать вечно, выселять только запечённые канвасы.

**Ключевой принцип: генерируем из seed, храним только дельты.**
`mulberry32(hash(buildingId, floor))` → планировка детерминирована. В сейв пишется: `seed` (уже есть из генератора города) + список изменённого (открытые/выломанные двери, обысканные контейнеры, разбитые окна). **~60–120 КБ на весь город.**

### Три состояния здания
- `shell` — запечённый спрайт, как сейчас. 99% города.
- `generated` — данные есть, коллизий/рендера нет. Триггер: игрок ближе **30 м** к двери (при 1.4 м/с это 21 с запаса — генерим в idle-бюджете 2 мс/кадр, вход без хитча).
- `active` — коллизии в гриде + запечённые полы + рендер. Радиус **40 м** от камеры, LRU-кап **12 зданий** (реально активно 3–6).

При входе: `shell.alpha 1 → 0.15` за 200 мс, интерьер fade-in 200 мс, крыша скрывается полностью.

## 2. ПЛАНИРОВКА: «коридор + нарезка», не BSP

Работает для 90% прямоугольных footprint. 5 шагов, ~0.4–0.8 мс на этаж.

```
1. СПИНА. Если min(w,h) >= 9: коридор вдоль длинной оси по центру.
   Иначе (глубина < 9): односторонний коридор у дальней стены.
2. ПОЛОСЫ. Две полосы глубиной d = (short - corridorW) / 2, snapped к целым тайлам.
3. НАРЕЗКА. Каждую полосу режем по длинной оси на комнаты шириной
   rand(minW, maxW), последний остаток < minW вливаем в предыдущую.
4. ДВЕРИ. Каждая комната → 1 дверь на стене к коридору,
   позиция в средних 60% ребра. Проверяем flood-fill от входа.
5. ПОДРАЗДЕЛЕНИЕ. Комната площадью > 28 м² → 1 разрез (depth<=2),
   отрезаем санузел 2×2 или кладовку 2×2 у внутренней стены.
```

### Таблица параметров

| Тип | Коридор | Глубина комнаты | Ширина | Лестниц | Окна | Besonderheit |
|---|---|---|---|---|---|---|
| Панелька | 2 м | 5 м | 8–11 м (квартира) | 1, центр | шаг 3 м | квартира делится на 3–4 подкомнаты |
| Магазин | нет | — | зал 70% / склад 20% / офис+WC 10% | 1 | витрина 70% фасадной стены | стеллажи 0.6 м, проходы 1.4 м |
| Школа | 3 м | 6 м | 7–9 м (класс 48 м²) | 2, по торцам | шаг 2.5 м | односторонний, шкафчики вдоль коридора |
| Больница | 3 м | 5 м | 4–6 м (палата 24 м²) | 2 | шаг 3 м | пост медсестры на стыке коридоров |

**Пример, панелька 24×12 = 288 м²:**
коридор 2×20 = 40 м², лестничная клетка 3×4 = 12 м², остаток 236 м² → **4 квартиры по ~55 м²** (2 на полосу), каждая → гостиная 4×4, спальня 3×3, кухня 3×3, санузел 2×2, прихожая 2×2. Итого **16–18 комнат + коридор** на этаж.

### Жёсткие инварианты (автотест на 200 случайных зданий)
- min комната **2×2 = 4 м²**, max **48 м²**
- коридор ≥ **2 тайла** (агент r=0.3 м, иначе два NPC не разойдутся)
- **100% комнат достижимы** flood-fill от входной двери через граф дверей
- ни одна дверь не заблокирована мебелью (проверка `occ` в 3×3 вокруг двери)
- вход всегда на фасадной (уличной) длинной стороне, 1–2 двери

### Мебель по роли комнаты (rule-based, не физика)
```
kitchen: холодильник 1×1 у стены (не у окна), плита 1×1, стол 2×1 в центре
bedroom: кровать 2×2 изголовьем к стене, шкаф 2×1 у противоположной
living:  диван 2×1, тумба 1×1, шкаф 2×1
bath:    сантехника 1×1 ×2
shop:    стеллажи рядами, шаг 2 м (0.6 стеллаж + 1.4 проход)
```
Постановка: только вдоль стен, отступ 0 тайлов от стены, зазор ≥ 1 тайл до двери. Контейнеры (лут) = холодильник, шкаф, тумба, стеллаж — **8–14 на квартиру/этаж**.

## 3. КОЛЛИЗИИ: одна grid + тайловые рёбра

### Стены — НЕ тела в grid, а битовая маска рёбер
Это дешевле и точнее AABB, и решает углы.

```js
// Круг игрока r=0.30 м против рёбер тайлов. Проверяем 3×3 = 9 тайлов.
// Ребро E тайла (i,j): отрезок x=i+1, y∈[j,j+1]
if (wall[idx] & E) {
  if (door[idx] & E && doorState[idx] !== CLOSED) { /* проходимо */ }
  else resolvePushX(px, i+1);
}
```
**~18 проверок рёбер на кадр на агента ≈ 1–2 мкс.** 200 агентов = 0.4 мс worst case, но внутри активно ≤ 40.

Углы: если круг перекрывает два смежных ребра —额外的 тест на вершину тайла (push по нормали к точке).

### Мебель — в существующую 16 м grid, но с этажом
```js
gridKey = (level << 24) | (cy << 12) | cx;   // level 0..7
```
Регистрируем тела **только активных зданий** (≤12). Типично: 6 зданий × 2 этажа × 35 тел ≈ **420 записей**. Ничтожно.

**Почему одна grid, а не отдельный слой:** зомби с улицы и игрок внутри — оба `level 0`, запрос «кто рядом» должен видеть обоих через дверной проём. Раздельные слои = дублирование broadphase + ручные cross-layer запросы у каждой двери. Не надо.

### Двери
| Состояние | Move | LOS | Path cost | Переход |
|---|---|---|---|---|
| closed | блок | блок | 1.0 | E, 0.3 с |
| open | проход | свободно | 1.4 | E |
| locked | блок | блок | ∞ / взлом | лом 6 с, ключ |
| broken | проход | свободно | 1.0 | зомби: HP 60, 15 урона/удар, 1.3 удара/с → **~3.5 с** |

**Критично: открытие двери НЕ перепекает чанк.** Дверь — динамический спрайт в per-frame проходе. Ноль ребейков во время игры.

### Pathfinding
- A* по тайлам, 8-связность с запретом срезания углов, рёбра-стены = барьеры, двери = ребра с ценой, лестницы = portal-ребра между уровнями.
- Лимит **400 expansion** на запрос; при переполнении — направление из room-графа (10–20 узлов/этаж).
- Бюджет: 200 зомби × репасс раз в 0.5–1.5 с ≈ 200 путей/с × 0.08 мс = **16 мс/с ≈ 1.6% CPU**. Внутри здания репасс 3 Гц, снаружи 0.7 Гц.

## 4. РЕНДЕР: диорама со срезом

### Высоты (1 м = 32 px)
| Элемент | Метры | px |
|---|---|---|
| Полная стена (дальние N/W) | 2.8 | 90 |
| Срезанная внутренняя перегородка | **1.0** | **32** |
| Ближние фасадные S/E | 0.35 (силл) | 11 |
| Дверное полотно | 1.0 (в срезе) | 32 |
| Этаж | 3.0 | 96 |
| Персонаж | 1.8 | 58 |

**Правило среза по нормали, не по расстоянию до игрока:** камера смотрит со стороны `+x+y`. Стена на ребре с нормалью `+x` (E) или `+y` (S) — ближняя, режем. N/W — дальние, полные, с окнами. Внутренние перегородки режем **все** до 1.0 м. Это даёт стабильную читаемую диораму без per-frame хакинга «какая стена мешает».

Срез обязательно с **кэпом 3 px светлее** — иначе стены читаются как бордюры.

### Порядок проходов
```
A. Уличные ground-чанки (существующая запечка)
B. Interior floor chunks активного здания/этажа   [BAKED]
C. Bucket-sorted pass: стены, мебель, двери, лут, зомби, игрок, чужие shell-спрайты
D. UI: подсветка контейнеров, промпт, имя комнаты
```

**Сортировка ведрами вместо sort():**
```js
bucket = Math.floor(x + y);   // 0 .. w+h  (~36 для 24×12)
// статика раскладывается по ведрам один раз при активации
// сущности — вставка O(1) каждый кадр
for (b = 0; b <= maxB; b++) drawAll(bucket[b]);
```
O(n) вместо O(n log n), n ≈ 300–600. **~0.3–0.6 мс.**

Многотайловая мебель: якорь = дальний угол `(x+w-1, y+h-1)`, спрайт рисуется один раз оттуда.

### Что печём, что рисуем каждый кадр

| Печём (чанк 8×8, ключ `cx,cy,level`) | Per-frame |
|---|---|
| полы по тайлам | стены (~150 сегментов) |
| тинт комнаты (8–12% alpha по роли) | мебель (~40) |
| **AO: градиентная тень 6 px от основания стен внутрь комнаты** | двери (~12) |
| статичный мусор/декали, плинтус | зомби/игрок/NPC |
| | подсветка лута, UI |

**AO — самый дешёвый прирост читаемости.** Без него диорама выглядит плоской.

Interior floor-чанк: `512×256 + 8 px pad = 528×272 ≈ 0.58 МБ`.
Этаж 24×12 = 3×2 = **6 чанков ≈ 3.1 МБ**, запечка **~2 мс**.
Этаж 30×24 = 4×3 = **12 чанков ≈ 6.3 МБ**, запечка **~4 мс**.

### Читаемость лута (обязательно)
- Контейнер необследован: тёплая точка-бейдж 12×12 над спрайтом (жёлтая).
- Обследован: спрайт десатурируется на 40%, бейдж → серая галочка.
- В радиусе 1.5 м: контурная обводка 2 px + иконка типа (холодильник/шкаф/полка) 16×16.
- Разный силуэт: холодильник 58 px, шкаф 64, стеллаж 51, тумба 24, кровать 16. Разница высот = узнаваемость без текста.

### Оптимизация стен (если понадобится)
Стены — коллинеарные пробеги. Пре-бейк спрайтов длины 1/2/3/4/6/8 × 2 ориентации × 3 высоты = 36 спрайтов. **150 draw → ~40 draw.** Пробеги резать по 4 тайла максимум, иначе поплывёт сортировка с сущностями.

## 5. ЭТАЖИ: MVP

- `floorHeight = 3.0 м = 96 px`. Рендер уровня L: `screenY -= L * 96`.
- **Лестничная клетка 3×4 м на одних и тех же (x,y) на всех этажах** (детерминировано из seed здания). Лестничный марш 2×3 тайла.
- Два portal-тайла: нижняя площадка (L), верхняя (L+1). Ребро в A* с ценой 3.0.

**MVP (итерация 3): дискретно.** E на тайле лестницы → fade 150 мс → смена `level`. Дёшево, не ломается, зомби используют то же ребро.

**Апгрейд (итерация 4): рампа.** `z` — float, `z = f(progress вдоль оси марша)`, `level = round(z/3)`. Проход 0.8 с. Оба этажа держим в LRU — это единственный момент, когда нужны 2 запечённых этажа.

### Рендер при level > 0
- Крыша своего здания скрыта.
- Текущий этаж при offset `-96*L`.
- Улица (ground-чанки) при offset 0, **alpha 0.55**, сущности улицы рисуем (видно зомби внизу — фича).
- Нижние этажи своего здания: MVP — не рисуем. Позже — alpha 0.4.

### Ограничения MVP
- Внешние стены верхних этажей глухие и твёрдые (в окно не выйти).
- Лифтов нет.
- Зомби используют лестницы только если `insideFlag` или уровень шума > порога.
- **Кап 12 зомби на здание, 40 суммарно в активных зданиях.**

## 6. ПРОИЗВОДИТЕЛЬНОСТЬ: бюджеты

| Ресурс | Число | Комментарий |
|---|---|---|
| Данные интерьеров, все 1400 | **24–32 МБ** | 924k тайлов × 8 Б, держим вечно |
| Генерация этажа | **0.4–0.8 мс** | spread 2 мс/кадр при подходе за 30 м |
| Запечка этажа | **2–4 мс** | 6–12 чанков, по 2 чанка/кадр |
| LRU запечённых interior-чанков | **96 шт ≈ 55 МБ** | ≈ 8–16 этажей |
| Активных зданий (коллизии+рендер) | **≤ 12**, радиус 40 м | реально 3–6 |
| Draw calls / кадр | **350–500** | ~2 мкс/call → 0.9 мс |
| Кадр внутри здания | **2.5–4 мс** | было 1 мс, запас 16.6 мс |
| Зомби внутри | ≤ 40, AI 30 Гц видимые / 10 Гц невидимые | |
| Path budget | ≤ 2 мс/кадр | очередь с приоритетом |
| Сейв города | **60–120 КБ** | seed + дельты |

**Стратегия генерации:** лениво по подходу (30 м), НЕ при входе. К моменту нажатия E всё готово → **вход без единого пропущенного кадра**. Данные не выселяем никогда (24 МБ), выселяем только канвасы.

**Что обязательно замерять:** `performance.now()` вокруг bake / gen / draw, счётчик draw calls, `canvasCount × w × h × 4` для оценки VRAM, p99 времени кадра за 60 с.

## 7. ПЛАН: 4 итерации

### Итерация 1 — «Коробка» (3–5 дней)
Один тип (панелька), один этаж, ручная планировка. Вход/выход, срез стен, тайловые коллизии, битовые маски рёбер. Мебели и лута нет.

**Приёмка:**
- Вход по E, **нет паузы > 16 мс** (замер).
- Игрок не проходит ни через одну стену, включая углы (тест: обход периметра + все перегородки).
- Выход восстанавливает shell за 1 кадр, камера не прыгает.
- 60 FPS при 200 зомби снаружи.
- Срез читается: скриншот, все 16 комнат визуально различимы.

### Итерация 2 — «Генератор + лут» (4–6 дней)
Алгоритм коридор+нарезка, 4 типа по таблице, роли комнат, двери (closed/open/locked), мебель, контейнеры на существующей лут-системе, AO и тинты в запечку, room labels.

**Приёмка:**
- 200 зданий сгенерированы, **100% комнат достижимы** (автотест flood-fill).
- Тот же seed → побайтово идентичная планировка.
- 0 случаев мебели в дверном проёме (автотест).
- Запечка этажа ≤ 6 мс, генерация ≤ 1 мс.
- После посещения 20 зданий память **+≤ 60 МБ**, LRU работает.
- Лут UI открывается, состояние «обыскано» сохраняется при выходе/входе.

### Итерация 3 — «Зомби + этажи» (4–6 дней)
Level в grid key, portal-рёбра (двери/лестницы) в A*, зомби входят и ломают двери, лестницы 2–4 этажа, offset-рендер уровней, шум (выстрел attracts в радиусе 60 м).

**Приёмка:**
- Зомби преследует игрока с улицы на 3-й этаж, **10/10 прогонов без застревания**.
- Вылом двери ~3.5 с, звук слышен.
- Ни одна сущность не «проваливается» между уровнями.
- 40 зомби внутри → 60 FPS, path budget ≤ 2 мс/кадр.
- Кап активных зданий не превышен при беге по улице 60 с.

### Итерация 4 — «Полировка + масштаб» (3–5 дней)
Плавная рампа лестниц, окна/LOS, per-room fog-of-war (комната ≤ 48 тайлов → visibility polygon дешёвый), приглушение уличного звука внутри, merged wall runs, тюнинг LRU, сейв дельт.

**Приёмка:**
- 30-минутная сессия: рост памяти **≤ 20 МБ** после прогрева.
- **p99 кадра ≤ 6 мс**, среднее ≤ 4 мс.
- Сейв всего города **≤ 200 КБ**, load ≤ 500 мс.
- Из окна видна улица и движущиеся зомби.
- Все 1400 зданий проходимы (автотест: телепорт + flood-fill по 100% зданий).

## Подводные камни, которые сэкономят тебе день каждый

1. **Shell-спрайты зданий должны рисоваться в общем sorted-проходе**, а не быть запечёнными в ground-чанк. Иначе игрок не сможет пройти за здание и cutaway не сработает. Проверь это первым делом.
2. **Соседнее здание к югу перекроет твой интерьер.** MVP: оставить как есть (PZ так же). Полировка: shell соседа, чей screen-rect пересекает интерьер, → alpha 0.5.
3. **Двери не в запечке.** Никогда. Иначе получишь 4 мс ребейк на каждое открытие.
4. **Многотайловая мебель и сортировка:** якорь строго дальний угол, иначе шкаф будет рисоваться поверх игрока, стоящего сзади.
5. **Коридор в 1 тайл** — NPC и зомби упрутся друг в друга навсегда. Минимум 2 тайла на магистральных коридорах.
6. **Не генерируй лут при входе в здание** — только при первом открытии контейнера (seed от `containerId`). Иначе 1400 зданий × 100 контейнеров на старте.
